LEGION + Keitaro — конверсия по нажатию кнопки
================================================

В ЭТОЙ ВЕРСИИ Lead = нажатие на «Отправить заявку» (не подтверждённая заявка).
- Даже если форма заполнена с ошибками и отправка браузером не начинается,
  клик по кнопке учитывается при наличии действительного subid.
- Чтобы избежать случайных повторов, для одного subid в пределах одной вкладки
  событие отправляется не более одного раза. Это не защита от намеренного спама.
- Без subid событие в Keitaro не отправляется.
- Данные клиента (имя, email, телефон, описание) в Keitaro не передаются.
- Отправка самой формы в Google Apps Script не менялась.
- Старый Meta Pixel удалён; дизайн не менялся.

ВАЖНО: ДЛЯ РАБОТЫ КОНВЕРСИИ НУЖНО НАСТРОИТЬ CLOUDFLARE PAGES
1. Загрузите весь архив (распакованные файлы) в GitHub репозиторий сайта.
   В корне должны быть index.html, js/ и functions/api/lead-click.js.
2. В Cloudflare Dashboard: Workers & Pages -> ваш Pages проект ->
   Settings -> Variables and Secrets (или Environment variables).
3. Создайте СЕКРЕТ KEITARO_POSTBACK_URL, значением которого будет ПОЛНЫЙ
   Postback URL из Keitaro -> Настройки -> Postback URL.
   Не публикуйте этот URL в GitHub, JS и скриншотах.
4. Добавьте секрет в Production и, если тестируете, Preview окружения.
   Затем выполните новый deployment, чтобы секрет применился.
5. Откройте сайт по ссылке Keitaro с subid, нажмите кнопку отправки;
   проверьте Keitaro -> Отчёты -> Конверсии / журнал postback.
   Этот тест учитывается как Lead! Удалите тестовую конверсию при необходимости.
6. В DevTools -> Network можно проверить запрос POST /api/lead-click:
   204 = получен успешный HTTP ответ от Keitaro; 503 = секрет не задан;
   502 = ошибка Keitaro; 404 = Pages Function не развернулась.

ОГРАНИЧЕНИЯ И БЕЗОПАСНОСТЬ
- Статическая публикация файлов без Pages Functions не отправит конверсию.
- 204 показывает лишь успех HTTP-запроса. Проверяйте запись конверсии в Keitaro.
- Публичный endpoint может получать поддельные запросы. Для рекламы с высоким
  объёмом трафика добавьте rate limiting / Turnstile / дополнительную проверку.
- В privacy.html сказано об использовании идентификатора перехода для аналитики.
- Код KEITARO_APPS_SCRIPT_EXAMPLE.gs оставлен как опциональный пример
  серверного учёта РЕАЛЬНО сохранённых заявок. В текущем варианте он НЕ нужен;
  НЕ включайте одновременно его postback lead, иначе получите дубли.
- Подмена сайта рекламным модераторам отличается от антибот-аналитики и может
  нарушать правила рекламных платформ.
